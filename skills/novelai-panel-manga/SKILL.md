# NovelAI 分镜漫画

把剧情或对白转成可分别粘贴到 NovelAI 的主提示词、逐格 Character Prompts 和负向提示词。保留用户指定的人物、版式、阅读顺序、台词与画风；用英文描述镜头，画内文字保留原语言。没有要求时不生成图片、不添加成人内容或画师混合。

## 核心：人物身份与槽位分开

先设计画格，再把画格内容映射到 character 槽。**一格一槽是简单场景的起点，不是固定限制**。人物身份、画格编号、槽位编号分别维护；两个人物、四个画格可以映射为 A、A、B、A 四槽，不要压缩成两个槽，也不要把人物数改成 `4girls`。

这是利用 Character Prompts、自然语言和可选位置引导分镜的方法，槽位本身不是固定边界的网格 API。需要检查生成图，不能承诺严格布局或人物绑定。

先区分两层信息：

- **人物锚点**：姓名/tag、发色、可辨识外貌、衣服和主要随身物。同一人物跨格重复这些短锚点；不要只说 “the same girl”。用户的外貌覆盖角色 tag 的默认外貌。
- **逐格变化**：画格位置、景别、机位、动作、表情、当前可见人物、气泡类型和说话者。这些写进对应槽，不能把某一格的伤势、表情或机位施加到整页。

同格出现两个人时，在该格槽内分别说明两人的身份、相对位置、动作和谁在说话，不合并属性。需要分别定位时，可用多个槽共同描述同一格，并重复相同的画格位置说明。手机、手部、环境等无人物特写也可单独占槽；该槽描述物体，不加 `girl` 或虚构人物。两种情况都要显式记录画格与槽位映射，不能检查“格数必须等于槽数”。

## 整页版式

用户要灵活布局、整页漫画或改编四格时，读 [references/flexible-layouts.md](references/flexible-layouts.md)。先按剧情确定主镜头、过渡、反应和揭示，再选择格数与面积；不要默认均分网格，也不要仅通过增加格数制造变化。

用短版式草图或分镜表表达：`画格 ID → 阅读顺序 → 区域/形状/层级 → 内容 → 槽位`。区分普通格、跨行/跨列的大格、嵌在宿主格内的插入格、延伸到纸边的出血格。画框外伸出的人物或气泡属于原格，不自动增加格数。只有复杂布局需要内部的归一化边界框；这些是编排记录，不是 NovelAI 的强制矩形裁切参数。

主提示词先讲页面分区和相邻关系，再讲阅读路线与格数。例如声明“五个主格＋一个插入格，共六格”，并说明中左竖格跨过右边上下两格的高度。每个槽重复本格的局部位置，不能只写泛泛的 “panel 3”。位置中心用于主体落点，格子大小与格线走向仍需自然语言说明。

沿用用户指定的阅读方向；未指定时沿用会话已建立的方向，并简短说明。通栏、跨行格和插入格要有明确的先后关系；画格 ID 是编排标签，未要求时不渲染编号。给气泡留空间，避免台词跨越格沟或破坏揭示顺序。倾斜格线、嵌套插入格与破框属于尝试性引导，不能承诺精确形状。

## 编排

1. 从输入提取人物表与分镜表：`格号 → 阅读顺序 → 位置/尺寸/层级 → 出场人物或物体 → 镜头/动作 → 说话者/气泡/原文 → 槽位`。用户已给完整分镜时直接采用；只给剧情时用适合情节的少量画格，并简短说明推定版式。把已有四格改成整页时可拆开反应、动作和细节，保留对白顺序与笑点，不无故加剧情。不要把四格、黑白或仙侠设为所有请求的固定要求。
2. 主提示词写页面信息：人物种类/人数、漫画画风、色彩、环境连续性、准确格数、各格位置/相对尺寸、阅读顺序。跨格重复人物属于同一故事人物，不按槽数增加人数。必要时明确 “The recurring appearances depict the same two characters.”。
3. 按画格阅读顺序分组输出 Character 1…N；同格多个槽相邻列出。每槽从明确的区域指示起句，例如 `In the tall middle-right panel, medium shot:`，然后写人物锚点或物体、动作/表情、环境细节与本格气泡。景别与可见内容要相容：脚踩血泊应让脚入镜，脸部特写不要同时要求全身装备清晰可见。
4. 台词归属写在本格自然语言中，例如 `A jagged speech bubble belonging to Sakiko reads "……滚开。别碰我。"`。音效没有说话者，内心话用 thought bubble；不把所有文字都变成对白。
5. 主提示词最末尾使用标准 `Text:`，按阅读顺序列出全部画内文字，条目之间空一行。`Text:` 后不再加画面说明、质量词或标签，避免它们变成画内文字。本格可重复引述原文以绑定位置；默认不再为每槽添加第二套 `Text:` 清单。
6. 负向单独输出，避免压制用户需要的漫画、文字、重复出场或网点。

## 文字、模型与位置

- 默认针对支持中文排字和整页漫画的 **V5**；用户指定模型时保留选择。V4/V4.5 的官方文字支持限英文，中文效果不能当作可靠能力；说明限制后可提供无字气泡/后期排字方案，不擅自翻译或删台词。
- `Text:` 是明确的文字入口。不要宣称用户样例里的 `teXt:` 大小写混合是控制网格的特殊指令。CLI 使用显式 `Text:`，不依赖网页前端自动提取引号内容。
- 原文逐字保留，包括标点和语气；长对白先给气泡留足空间，必要时按语义换行，去掉新增换行后必须还原原文。仍过长时建议精简或拆格，不默默改写。官方总文字长度上限含空白和换行：V4/V4.5 为 118 字符，V5 Curated 为 374，V5 Full 为 750；上限不保证逐字正确。
- 人数标签放主提示词；人物槽使用 `girl`/`boy` 等无数字称谓，物体槽不加人物称谓。`Character 1`/`char1` 是交付标签，不是应拼进主提示词的专用语法。网页中分别粘贴各槽；只有用户要求单串且没有独立槽时，才使用官方 `base | character | character` 形式。
- 优先保留用户已有的位置模式。需要辅助定位时给每槽可选归一化 `(x,y)` 中心：左上为 `(0,0)`，右下为 `(1,1)`，与阅读顺序和自然语言一致。坐标只是主体位置，不是格子四边；V4/V4.5 位置受 5×5 网格约束。复杂版式先用自然语言表达边界，不虚构强制网格参数。
- 不使用 SD 的 `(tag:1.2)`、`BREAK` 或未经核实的 char 分隔符。通常自然语言即可；确需强调才使用 NovelAI 数字权重如 `1.2::monochrome::`，不把整页对白放进权重。

## 防止负向与预设互相抵消

默认负向可从短列表开始：`lowres, worst quality, bad quality, jpeg artifacts, bad anatomy, bad hands, watermark, signature`，再按实际失败调整。

不要默认加入 `text, chinese text, speech bubble, comic, manga, panels, multiple views, duplicate, monochrome, screentone`：它们可能正是任务需要的内容。不要从单幅插画或其他 NAI 技能继承 `no text`、全局 `solo`、禁止重复人物或压制多视图的权重。

文字/短音效被抑制时关闭自动 Quality Tags，手动把所需质量词加在 `Text:` 之前；检查 UC 预设是否带 `multiple views`、`screentone`、`comic` 等冲突项。CLI 测试时显式控制这些开关，不能只检查手写负向。

## 交付格式

默认只交付一版，解释用中文，提示词块只含要粘贴的内容：

1. 一句槽位映射（例如 `char1=A／上格；char2=A／中左；char3=B／中右；char4=A／下格`）；灵活版式先附一幅简洁草图或分镜表，标明阅读路线和插入格的宿主。
2. **主提示词**：一个完整代码块，`Text:` 清单在块末尾。
3. **Character 1…N**：每槽独立代码块；标题注明画格和人物/物体，同格多个槽要明确归组，位置坐标需要时写在标题旁、块外。
4. **负向提示词**：独立代码块。
5. 必要时一两句说明模型、推定或尚未验证的限制。

用户要求只给提示词时省略解释。不要只返回一个混合 `<PROMPT>`，导致用户无法分别粘贴到槽位。

输出前核对：每格都有内容映射、每槽都有格位；主格与插入格计数一致；跨行格与邻格关系无矛盾、普通格不意外重叠；插入格有宿主且不盖住关键台词；每句文字有格位和类型；重复人物锚点一致；服装与镜头自洽；`Text:` 顺序正确；负向/自动预设不与漫画目标冲突。纯文本生成不需要联网或图片测试。

## 测试与资料

- 用户要样例或以竹林相遇页为参考时读 [references/bamboo-four-panel.md](references/bamboo-four-panel.md)。它展示两个人物、四个槽，不能据此把所有任务限制为这两个人物或四格。
- 用户授权 CLI 生图测试时读 [references/novelai-cli.md](references/novelai-cli.md)。先 dry-run 检查真实 payload，再做一张预览并看图；必要时至多做一次有明确假设的修订，不无限刷图。保留请求、参数、seed、图像和检查结果，不将一次样图当作稳定成功率。
- 需要核对版本、语法或限制时读 [references/sources.md](references/sources.md) 并按需核查官方资料。不要把提示词编排建议描述成官方硬性语法。
